# BibiBike Leads

Отдельный сервис поиска заявленного инвестиционного намерения в заранее
разрешённых публичных Telegram-сообществах и ручной обработки найденных
сообщений в CRM.

Проект не является частью рабочего бота смен и не использует его базу данных.
Пользовательский Telegram-аккаунт запускается как read-only Reader внутри
одного процесса BotHost. Он не должен собирать участников, вступать в сообщества, писать
сообщения, ставить реакции или рассылать личные сообщения.

## Текущий этап

Рабочий вертикальный срез пилота:

- отдельная SQLite-схема;
- allowlist публичных источников;
- объяснимый фильтр намерения;
- определение города по тексту или источнику;
- идемпотентная запись кандидатов;
- история создания и переклассификации лида;
- каталог ещё не активированных A/B-кандидатов;
- защищённая авторизация отдельной user-сессии через Mini App;
- проверка типа, username, членства и `chat_id` без чтения сообщений;
- ручное включение источников из проверенного каталога;
- live-only `NewMessage`/`MessageEdited` Reader с числовым allowlist;
- долговечная SQLite-очередь, heartbeat и журнал действий администратора;
- тесты дедупликации, fail-closed настроек и запретов Reader.

Reader реализован, но по умолчанию остановлен аварийным переключателем
`COLLECTOR_ENABLED=false`. Текущий код не вступает в группы, не читает историю
или участников и не отправляет сообщения.

Полный план находится в [docs/SPEC.md](docs/SPEC.md).

Защищённый вход пользовательского Reader-аккаунта через Telegram Mini App и
развёртывание на BotHost описаны в [docs/BOTHOST.md](docs/BOTHOST.md). Экран
входа обслуживается backend BotHost; GitHub хранит исходники, но не секреты и
не файл сессии.

Результаты первого поиска открытых сообществ и стартовый список A/B находятся
в [research/SOURCE-DISCOVERY.md](research/SOURCE-DISCOVERY.md). Кандидаты
намеренно не включаются автоматически: администратор вручную вступает,
проверяет источник в Mini App и отдельным действием включает его.

## Локальный запуск

Требуется Python 3.11+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python -m app.cli init-db
python -m app.cli seed-pilot
python -m app.cli list-sources
python -m app.cli list-candidates --priority A
python -m app.cli classify "Ищу франшизу, готов вложить 7 млн в Екатеринбурге"
python -m unittest discover -s tests -v
```

Команда `seed-pilot` пока оставлена как необязательный пример распознавания
города. Для федеральных источников город указывать не нужно. Команда ниже
регистрирует только непроверенный источник для локальной отладки. Такая запись
всегда выключена и не может быть активирована:

```powershell
python -m app.cli add-source `
  --chat-id -1001234567890 `
  --handle public_business_chat `
  --title "Публичный бизнес-чат"
```

Рабочий источник нужно импортировать из свежего `ready`-отчёта resolver:

```powershell
python -m app.cli register-ready-source `
  --report ./data/source-resolution.json `
  --handle businessclass_rbc
```

И он тоже остаётся выключенным. Включение — отдельное явное действие после
smoke-test. В production это делается кнопкой Mini App; локальный резервный
CLI-вариант выглядит так:

```powershell
python -m app.cli set-source --chat-id -1001234567890 --enable
```

## Подключение отдельного Telegram-аккаунта

Подробный порядок находится в [docs/TELEGRAM-SETUP.md](docs/TELEGRAM-SETUP.md).
Коротко:

```powershell
# Сначала заполнить TELEGRAM_API_ID и TELEGRAM_API_HASH только в локальном .env
python -m reader.cli authorize

# Затем записать выведенный TELEGRAM_EXPECTED_USER_ID в локальный .env,
# вручную вступить в выбранную группу через официальный Telegram и проверить её
python -m reader.cli resolve-sources --handle businessclass_rbc
```

Отчёт появится в `data/source-resolution.json` и ничего не активирует. Затем
выбранный результат можно зарегистрировать командой `register-ready-source`.

## Неподвижные ограничения пилота

- только явно включённые публичные источники с username;
- только новые сообщения после запуска, без массовой истории;
- `READER_CATCHUP_LIMIT=0` на всём первом пилоте;
- никакого сбора участников и профилей авторов;
- никакой автоматической коммуникации;
- пользовательская `.session` никогда не попадает в Git;
- `COLLECTOR_ENABLED=false` является аварийным выключателем;
- нерелевантные кандидаты имеют короткий срок хранения;
- исходная ссылка строится сервером из allowlist, а не принимается на доверии.

## Размещение сайта

Административный `index.html` должен отдаваться тем же HTTPS-приложением
BotHost, что и API: так проверка Telegram Mini App остаётся same-origin.
GitHub хранит исходники и выполняет деплой, но не хранит рабочую сессию,
SQLite-базу или секреты. Они находятся только в переменных BotHost и
постоянной папке `/app/data`.
