# Развёртывание Telegram Mini App

## 1. Подготовить бота

1. Создать бота через `@BotFather` или использовать существующего.
2. Сохранить токен только в переменных окружения хостинга как `BOT_TOKEN`.
3. После появления HTTPS-адреса открыть BotFather → **Bot Settings → Configure Mini App → Enable Mini App** и указать этот адрес.
4. Дополнительно настроить **Menu Button**, чтобы журнал открывался одной кнопкой из диалога с ботом.

Telegram передаёт Mini App поле `initData`. Backend этого проекта проверяет подпись, срок действия и Telegram ID. Значения из `initDataUnsafe` серверу не доверяются.

## 2. Переменные окружения

```dotenv
BOT_TOKEN=<токен из BotFather>
BOT_USERNAME=<имя того же бота без @>
DATABASE_PATH=/app/data/trader_journal.sqlite3
PORT=8080
MAX_AUTH_AGE_SECONDS=86400
DEV_MODE=false
```

BotHost обычно создаёт `BOT_TOKEN` автоматически из поля токена бота. Для совместимости приложение также принимает `TELEGRAM_BOT_TOKEN`, `API_TOKEN` и `TOKEN`.

## 3. Включить вход на сайте

Обычная ссылка BotHost открывает веб-версию журнала. Для входа через браузер:

1. Скопируйте HTTPS-домен приложения без пути, например `journal.example.com`.
2. В `@BotFather` выберите того же бота и откройте **Bot Settings → Login Widget / Web Login**. Добавьте HTTPS-адрес сайта в разрешённые URL. В старом интерфейсе BotFather это делается командой `/setdomain`.
3. Добавьте в BotHost переменную `BOT_USERNAME` — имя бота без символа `@`.
4. Выполните **новый деплой**, затем откройте домен BotHost в обычном браузере.

Mini App подтверждает пользователя через `initData`, а сайт — через Telegram Login и защищённую HTTP-only cookie. Оба варианта используют один Telegram ID и одну базу, поэтому записи синхронизируются автоматически. Не создавайте для сайта отдельного бота: тогда Telegram ID останется тем же, но настройка и ожидания пользователя будут запутаны.

Для закрытого приложения можно указать только ваши два Telegram ID:

```dotenv
ALLOWED_USER_IDS=111111111,222222222
```

Если список пуст, войти сможет любой человек, открывший Mini App через этого бота, но чужие личные данные и команды ему недоступны.

## 4. Постоянное хранение

Каталог базы должен переживать обновления контейнера. Для BotHost используется `/app/data`. Там же в `uploads/weekly_plans` сохраняются фотографии недельных торговых планов. Перед переносом или переустановкой остановите приложение и скопируйте весь каталог `/app/data`, а не только файл `trader_journal.sqlite3`.

## 5. Настройка BotHost

Этот проект использует **Python**. Клиентский код хранится без расширения `.js` и отдаётся браузеру по адресу `/client`, чтобы автодетектор BotHost не мог принять его за серверную точку входа.

В карточке приложения BotHost укажите:

- язык / библиотека: **Python**;
- **Дополнительные настройки → Главный файл (точка входа):** `main.py`;
- домен: включён;
- порт: значение переменной `PORT` (обычно `8080`).

После изменения точки входа нажмите **«Новый деплой»**. Обычного перезапуска старого контейнера недостаточно.

Команда запуска:

```text
python main.py
```

Приложение слушает `0.0.0.0` и порт из `PORT`. Проверка состояния доступна по `/health`.

Если BotHost всё равно выбирает Node.js, включите **«Использовать собственный Dockerfile»** и выполните новый деплой. В корне репозитория уже есть `Dockerfile` с командой `python main.py`.

Ошибка `ReferenceError: window is not defined` означает, что хост попытался запустить клиентский JavaScript через Node.js. Файл с `window.Telegram` не является сервером и не должен быть выбран точкой входа.

## 6. Проверка перед публикацией

- `DEV_MODE=false`;
- HTTPS работает без предупреждений сертификата;
- `BOT_TOKEN` отсутствует в GitHub;
- Mini App открывается именно из Telegram;
- домен BotHost показывает кнопку Telegram Login и после входа открывает те же записи;
- каждый участник видит только свои личные записи;
- код команды передан только другу;
- каталог базы является постоянным.

Официальная документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps) и [Telegram Login Widget](https://core.telegram.org/widgets/login/).
