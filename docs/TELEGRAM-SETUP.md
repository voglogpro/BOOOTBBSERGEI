# Подключение отдельного Telegram-аккаунта

На этом шаге мы только создаём локальную user-сессию и проверяем заранее
отобранные публичные группы. Сбор новых сообщений пока не запускается.

## 1. Подготовить отдельный аккаунт

- Использовать отдельную SIM и аккаунт, не основной аккаунт Кирилла.
- Включить двухэтапную аутентификацию и резервную почту.
- Не использовать этот аккаунт для рассылок, реакций и массовых вступлений.
- Вступать в выбранные группы вручную через официальный Telegram-клиент.

## 2. Получить API-реквизиты

Создать приложение на [my.telegram.org](https://my.telegram.org/) и получить
собственные `api_id` и `api_hash`. Не копировать чужие реквизиты.

Скопировать `.env.example` в `.env` и заполнить только локально:

```dotenv
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=32_шестнадцатеричных_символа
TELEGRAM_SESSION_PATH=./data/telegram/reader.session
```

Телефон, одноразовый код и пароль 2FA в `.env` не записываются.

## 3. Один раз авторизоваться

```powershell
python -m reader.cli authorize
```

Команда запросит телефон, код и при необходимости 2FA только в терминале. После
успеха она выведет числовой ID аккаунта. Добавить его в локальный `.env`:

```dotenv
TELEGRAM_EXPECTED_USER_ID=123456789
```

Все последующие административные команды завершаются с ошибкой, если session
не авторизована, относится к боту или принадлежит другому user ID.

## 4. Выбрать и вручную открыть один источник

Посмотреть исследованный каталог без подключения к Telegram:

```powershell
python -m app.cli list-candidates --priority A
```

Для первого smoke-test выбрать только одну группу, открыть её ссылку, прочитать
правила и вручную вступить через официальный клиент. Не вступать сразу во все
группы.

## 5. Получить проверочный отчёт

```powershell
python -m reader.cli resolve-sources --handle businessclass_rbc
```

Заменить `businessclass_rbc` на выбранный handle из каталога. `--handle` можно
повторить, но за один запуск допускается не более десяти источников.

Команда делает не более десяти последовательных `get_entity`-проверок и
останавливается при FloodWait. Она не читает сообщения/историю, не получает
участников, не вступает и не пишет. Возможные статусы:

- `ready` — публичная обычная группа, аккаунт уже состоит в ней, ID получен;
- `not_joined` — требуется ручное вступление;
- `not_public_group` — это канал, приватная сущность или не группа;
- `username_mismatch` — username изменился и требует повторной ручной проверки;
- `unsupported_forum` — темы пока не поддержаны;
- `unavailable` — источник недоступен или аккаунт заблокирован в нём;
- `rate_limited` — Telegram потребовал паузу, дальнейшие запросы прекращены;
- `skipped_after_rate_limit` — источник не запрашивался после остановки пакета.

При FloodWait точное время запрета сохраняется рядом с session. До его истечения
следующий запуск завершится до подключения к Telegram. Удалять cooldown-файл,
чтобы обойти ожидание, нельзя.

Результат сохраняется в `data/source-resolution.json`. Папка `data` исключена
из Git. Отчёт не добавляет источник в Core и не включает мониторинг.

## 6. Зарегистрировать только результат `ready`

Отчёт должен быть не старше 24 часов. Команда сверяет статус, отрицательный ID
и точное совпадение handle, затем создаёт в Core выключенную запись:

```powershell
python -m app.cli register-ready-source `
  --report ./data/source-resolution.json `
  --handle businessclass_rbc
```

Обычный `add-source` не создаёт проверку, поэтому такую запись нельзя включить.
Повторный `add-source` для уже проверенного источника сбрасывает проверку и снова
выключает его. До реализации live-reader `set-source --enable` не нужен.

## 7. Защитить session

Файл `.session` фактически даёт доступ к аккаунту:

- не отправлять его в чат и не загружать в GitHub, GitHub Pages или бэкапы CRM;
- держать `.env` и session в закрытой директории на постоянном диске;
- не запускать два процесса с одним session-файлом;
- завершать клиент через `disconnect()`, никогда не через `log_out()`;
- при утечке немедленно завершить эту сессию в официальном Telegram-клиенте.

На Windows `chmod` сам по себе не гарантирует закрытый ACL. Перед production
нужно отдельно ограничить права каталога `data` учётной записью сервиса.
